# Описание проекта и требования (Версия 1.0)

## 1. О приложении
**Student Poll System** — это веб-платформа для проведения студенческих опросов, сбора мнений и последующей аналитики для принятия решений. 

**Роли пользователей:**
- **Студент (User):** основной пользователь, который создает опросы, голосует и просматривает результаты.
- **Администратор (Admin):** модератор, который следит за соблюдением правил, может удалять некорректные опросы и управлять пользователями.

**Глоссарий (термины):**
- **Опрос (Poll):** сущность, содержащая вопрос, варианты ответов, метаданные (автор, дата) и необязательный баннер.
- **Баннер:** изображение, прикрепленное к опросу для визуального оформления (хранится в S3).
- **Голос (Vote):** факт выбора студентом одного из вариантов ответа в активном опросе (один студент = один голос в одном опросе).

## 2. Требования к функционалу и ограничения

### 2.1. Функциональные требования (FR)
| ID | Требование | Приоритет | Состояние | Признак выполнения |
|:---|:---|:---:|:---:|:---|
| **FR-1** | Студент может зарегистрироваться в системе, указав номер студенческого билета и пароль. | Обязательно | Нужно доработать | В БД появляется новая запись пользователя, выдается JWT-токен. |
| **FR-2** | Студент может войти в систему (аутентификация) и выйти из неё (разрыв сессии). | Обязательно | Уже есть | Успешный вход возвращает access/refresh токены, выход аннулирует сессию. |
| **FR-3** | Студент может создать новый опрос, указав текст вопроса и минимум два варианта ответа. | Обязательно | Уже есть | Опрос появляется в общем списке, автор закрепляется за записью. |
| **FR-4** | Студент может прикрепить файл-изображение (баннер) к создаваемому или существующему опросу. | Желательно | Уже есть | Файл загружается в S3, ссылка на него сохраняется в записи опроса в БД. |
| **FR-5** | Студент может отдать один голос в активном опросе, выбрав один из вариантов ответа. | Обязательно | Уже есть | Счетчик выбранного варианта увеличивается, повторный голос блокируется. |
| **FR-6** | Администратор может удалять опросы, нарушающие правила платформы. | Обязательно | Нужно доработать | Опрос помечается как удаленный или физически удаляется из БД и S3. |
| **FR-7** | Студент может просмотреть текущие результаты опроса и проверить, был ли учтен его голос. | Желательно | Уже есть | Отображается диаграмма/проценты и статус "Вы проголосовали". |

### 2.2. Нефункциональные требования (NFR)
| ID | Ограничение | Критерий проверки |
|:---|:---|:---|
| **NFR-1** | **Производительность:** Время отклика API при создании опроса или голосовании не должно превышать 2 секунд при нагрузке до 100 RPS. | Нагрузочное тестирование (например, через Locust или k6). |
| **NFR-2** | **Безопасность:** Пароли пользователей должны храниться только в хэшированном виде (bcrypt). Доступ к API защищен JWT-токенами. | Код-ревью, попытка запроса без токена возвращает 401 Unauthorized. |
| **NFR-3** | **Хранение данных:** Текстовые данные и связи хранятся в PostgreSQL, файлы (баннеры) — в объектном хранилище MinIO (S3-compatible). | Проверка конфигурации подключения и фактического сохранения файла в бакете MinIO. |
| **NFR-4** | **Валидация:** Система должна принимать файлы баннеров только форматов `.jpg`, `.png`, `.webp` размером не более 5 МБ. | Попытка загрузить `.exe` или файл 10 МБ возвращает ошибку 400 Bad Request. |

## 3. Пользовательские сценарии (US)

### US-1: Создание опроса с баннером (связан с FR-3, FR-4)
- **Я как:** Студент
- **Имею:** Действующую сессию (JWT-токен), файл изображения `banner.png` (2 МБ), текст вопроса "Где провести выпускной?" и 3 варианта ответа.
- **Делаю:** 
  1. Перехожу на страницу `/polls/create`.
  2. Заполняю поле вопроса и добавляю варианты ответов.
  3. Перетаскиваю файл `banner.png` в зону загрузки.
  4. Нажимаю кнопку "Создать опрос".
- **Получаю:** Уведомление "Опрос успешно создан". Опрос появляется в моей ленте и в общей ленте с прикрепленным баннером.

**Обработка ошибки (US-1-Error):**
- **Входные данные:** Тот же сценарий, но пытаюсь загрузить файл `script.exe` (или файл размером 10 МБ).
- **Реакция системы:** Загрузка прерывается. Система **не создает** опрос и возвращает сообщение: *"Ошибка: недопустимый формат файла или превышен размер (макс. 5 МБ, форматы: jpg, png, webp)"* (HTTP 400).

---

### US-2: Голосование в опросе (связан с FR-5)
- **Я как:** Студент
- **Имею:** Действующую сессию, нахожусь на странице активного опроса, ранее не голосовал в нём.
- **Делаю:** 
  1. Выбираю радиокнопку напротив варианта "В парке".
  2. Нажимаю кнопку "Проголосовать".
- **Получаю:** Уведомление "Ваш голос учтен". Кнопка голосования блокируется, отображаются актуальные проценты результатов.

**Обработка ошибки (US-2-Error):**
- **Входные данные:** Я пытаюсь проголосовать в том же опросе второй раз (или мой токен протух).
- **Реакция системы:** Система **не изменяет** счетчики. Возвращается сообщение: *"Вы уже проголосовали в этом опросе"* (HTTP 409 Conflict) или *"Требуется авторизация"* (HTTP 401).

---

### US-3: Удаление некорректного опроса (связан с FR-6)
- **Я как:** Администратор
- **Имею:** Права администратора, вижу в ленте опрос с оскорбительным содержанием.
- **Делаю:** 
  1. Нажимаю кнопку "Удалить" в карточке этого опроса.
  2. Подтверждаю действие во всплывающем окне.
- **Получаю:** Уведомление "Опрос удален". Опрос исчезает из публичной ленты, его запись удаляется из БД, а файл баннера удаляется из S3.

**Обработка ошибки (US-3-Error):**
- **Входные данные:** Обычный студент (без прав админа) пытается отправить DELETE-запрос на эндпоинт удаления чужого опроса.
- **Реакция системы:** Система **не удаляет** опрос. Возвращается ошибка *"Доступ запрещен: недостаточно прав"* (HTTP 403 Forbidden).

## 4. Модели системы
*(Ссылки на диаграммы, исходники которых находятся в папке `docs/diagrams/`)*

1. **Контекст:** Диаграмма контекста (C4 Context) показывает взаимодействие Студента и Администратора с системой "Student Poll System", а также зависимость системы от внешних сервисов: PostgreSQL (хранение данных) и MinIO S3 (хранение файлов). 
   - *Файл:* `docs/diagrams/context.puml` (или `.mmd`)
   - *Иллюстрирует:* Границы системы и внешние зависимости.

2. **Взаимодействие:** 
   - Диаграмма вариантов использования (Use Case), связывающая роли с FR-1...FR-7.
   - Диаграмма последовательности (Sequence) для сценария **US-1** (создание опроса с загрузкой файла в S3).
   - *Файлы:* `docs/diagrams/use_case.puml`, `docs/diagrams/sequence_upload.puml`

3. **Структура:** Диаграмма классов (или ER-диаграмма базы данных), отражающая сущности: `User`, `Poll`, `Option`, `Vote`, `FileAttachment` с их атрибутами и связями (1 ко многим, многие ко многим).
   - *Файл:* `docs/diagrams/class_diagram.puml`

4. **События:** Диаграмма состояний (State Machine) для сущности `Poll` (Опрос), отражающая переходы: `Черновик` → `Активный` → `Завершен` или `Удален`.
   - *Файл:* `docs/diagrams/poll_states.puml`
