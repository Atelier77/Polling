# Контракт программного интерфейса: Создание опроса

## 1. Общие сведения об операции

| Поле | Значение |
|:---|:---|
| **Операция** | `POST /api/polls/` |
| **Назначение** | Создание нового опроса с вариантами ответов и его немедленная публикация |
| **Связанный сценарий** | [US-1](01-requirements.md#us-1-создание-опроса-с-баннером) |
| **Связанное требование** | [FR-3](01-requirements.md#21-функциональные-требования-fr) |
| **Протокол** | HTTP/1.1, REST |
| **Формат обмена** | JSON (`application/json`) |
| **Ссылка на реализацию** | `src/backend/src/api/routes/polls.py` → функция `create_poll` |
| **Ссылка на схему запроса** | `src/backend/src/schemas/poll.py` → модель `PollCreate` |
| **Ссылка на схему ответа** | `src/backend/src/schemas/poll.py` → модель `PollResponse` |

---

## 2. Вызывающая сторона и способ вызова

**Кто вызывает:** клиентское приложение (React-фронтенд) от имени авторизованного пользователя с ролью `ADMIN`.

**Как вызвать:** отправить HTTP-запрос методом `POST` на адрес `/api/polls/` с заголовком авторизации и телом в формате JSON.

```http
POST /api/polls/ HTTP/1.1
Host: localhost:8000
Content-Type: application/json
Authorization: Bearer <JWT_ACCESS_TOKEN>
```

## 3. Входные данные (Request)

### 3.1. Заголовки

| Заголовок | Обязательность | Значение |
|:---|:---:|:---|
| `Content-Type` | Да | `application/json` |
| `Authorization` | Да | `Bearer <access_token>` — JWT-токен, полученный через `/api/auth/login` |

### 3.2. Тело запроса (JSON)

Модель: `PollCreate`

| Поле | Тип | Обязательность | Ограничения | Описание |
|:---|:---|:---:|:---|:---|
| `title` | `string` | Да | 5–200 символов | Название опроса |
| `description` | `string` | Да | 10–1000 символов | Описание/вопрос опроса |
| `end_date` | `string` (ISO 8601) | Да | Должна быть в будущем (`> now()`) | Дата и время окончания голосования |
| `options` | `array[OptionCreate]` | Да | 2–10 элементов | Варианты ответов |

Вложенная модель `OptionCreate`:

| Поле | Тип | Обязательность | Ограничения | Описание |
|:---|:---|:---:|:---|:---|
| `text` | `string` | Да | 1–500 символов | Текст варианта ответа |

### 3.3. Условия вызова (preconditions)

1. Пользователь аутентифицирован (валидный JWT в заголовке).
2. Роль пользователя — `ADMIN`.
3. Поле `end_date` должно указывать на момент времени в будущем.
4. Массив `options` должен содержать от 2 до 10 элементов.
5. Текст каждого варианта ответа должен быть уникальным в рамках одного опроса (проверка на уровне сервиса).

---

## 4. Результат вызова (Response)

### 4.1. Успешный вызов

**Код ответа:** `201 Created`

**Тело ответа (JSON):** модель `PollResponse`

| Поле | Тип | Описание |
|:---|:---|:---|
| `id` | `integer` | Уникальный идентификатор созданного опроса |
| `title` | `string` | Название опроса |
| `description` | `string` | Описание |
| `status` | `string` | Статус опроса (всегда `"active"` при создании) |
| `author_id` | `integer` | ID пользователя-создателя |
| `end_date` | `string` (ISO 8601) | Дата окончания голосования |
| `created_at` | `string` (ISO 8601) | Время создания |
| `options` | `array[OptionResponse]` | Список вариантов ответов с присвоенными `id` и начальным счётчиком `votes: 0` |

### 4.2. Характерная ошибка: нарушение валидации

**Код ответа:** `422 Unprocessable Entity`

**Ситуация:** клиент передал данные, не удовлетворяющие ограничениям модели `PollCreate` (например, слишком короткий заголовок, пустой массив вариантов, дата в прошлом).

**Тело ответа:**

```json
{
  "success": false,
  "error": "Ошибка валидации данных",
  "details": [
    {
      "field": "title",
      "message": "String should have at least 5 characters",
      "type": "string_too_short"
    }
  ]
}
```

**Код ответа:**  `401 Unauthorized`

**Ситуация:** отсутствует или невалиден JWT-токен

**Код ответа:** `403 Forbidden`

**Ситуация:** Пользователь аутентифицирован, но не имеет роли ADMIN

## 6. Идемпотентность и побочные эффекты

- Операция **не идемпотентна**: каждый успешный вызов создаёт новую запись в таблице `polls` и новые записи в таблице `options`.
- **Побочные эффекты:**
  - В БД создаётся запись `Poll` со статусом `ACTIVE`.
  - В БД создаются записи `Option` (по одной на каждый элемент массива `options`).
  - Счётчики голосов (`votes`) для всех вариантов инициализируются нулём.
  - В журнале аудита фиксируется факт создания опроса пользователем `author_id`.
